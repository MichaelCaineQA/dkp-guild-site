# AGENTS.md — правила проекта для людей и ИИ-ассистентов

ДКП-система гильдии в Throne and Liberty. **Сначала прочитай
[docs/PLAN.md](docs/PLAN.md)** — это мастер-спека: требования, механики
(разделы 2 и 6), зафиксированные решения гильдии (раздел 12). Если код
противоречит плану — правильнее план; менять план без явной просьбы владельца
нельзя.

## Карта репозитория

- `apps/web` — Next.js (App Router, TypeScript strict)
- `apps/api` — NestJS; Prisma-схема: `apps/api/prisma/schema.prisma`
- `packages/shared` — общие типы, zod-схемы, чистая логика ядра
- `docs/PLAN.md` — план и решения гильдии
- CI: `.github/workflows/ci.yml` — lint → typecheck → test → build → audit

## Команды

```bash
pnpm install
docker compose up -d     # PostgreSQL + Redis
pnpm db:generate         # после изменения Prisma-схемы
pnpm db:migrate          # создать/применить миграции (локально)
pnpm dev                 # web: http://localhost:3000, api: :3001
pnpm lint && pnpm typecheck && pnpm test && pnpm build   # перед PR
```

## Непреложные правила архитектуры

1. **Журнал ДКП append-only**: записи `DkpEntry` не правятся и не удаляются,
   «исправление» — новая запись. Баланс = сумма записей (`computeBalance`
   в `packages/shared`).
2. **Чек-ин коды хранятся только хэшем**; сам код видит лишь РЛ ивента.
3. **Все игровые правила (платы, наценки, окна кодов, длительности лотов) —
   в модели `Setting`**, не константами в коде.
4. **Любое ручное действие** (отметки посещения, назначение победителя лота,
   смена ролей) **обязано писать запись в `AuditLog`** с комментарием.
5. Время — UTC в БД, отображение в таймзоне игрока. Игровой цикл день/ночь —
   `getGamePhase` в `packages/shared`, якорь цикла — настройка гильдии.
6. Логика ядра (ДКП, права, окна кодов, анти-снайп) живёт в
   `packages/shared` и покрывается юнит-тестами **в том же PR**.
7. UI — только русский язык.

## Процесс

- Ветки `feature/*`, `fix/*`, `chore/*`, `docs/*` → PR в `main`. Ревью
  опционально, зелёный CI обязателен. Подробности: [CONTRIBUTING.md](CONTRIBUTING.md).
- Коммиты: `feat|fix|chore|docs|refactor: суть изменения` (по-русски можно).
- Секреты — только в `.env` (образец `.env.example`), никогда в коде и истории.

## Для ИИ-ассистентов

- Не меняй `docs/PLAN.md` и игровые правила без явной просьбы владельца.
- Новые настройки добавляй в `Setting` + zod-схему в `packages/shared`.
- Не добавляй зависимости без необходимости; добавил — обнови
  `pnpm-lock.yaml` тем же коммитом (`pnpm install && git add pnpm-lock.yaml`).
- Миграции применяй только к локальной базе (`docker compose up -d`);
  прод-миграции выполняет деплой.
- После правок UI прикладывай скриншот в PR.
