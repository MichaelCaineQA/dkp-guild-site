# Известные проблемы и ловушки

Проверено по документации 2026-11-08. Это не список открытых багов приложения:
актуальные задачи и статусы ведутся в GitHub Issues. Ниже отдельно отмечены
расхождения текстов и документированные симптомы окружения; воспроизведение
не подразумевается, если оно явно не указано.

## Windows: порты Docker заняты или зарезервированы

- Источник: README.md, «Вариант A», блок «Если порты заняты/заблокированы».
- Симптом: `ports are not available` / `EACCES`; возможна резервация WinNAT.
- Диагностика: `netsh interface ipv4 show excludedportrange protocol=tcp`.
- Документированный обход: в корневом `.env` согласовать `SITE_WEB_PORT`,
  `SITE_API_PORT`, `NEXT_PUBLIC_API_URL` и `WEB_URL`; также обновить
  `DISCORD_CALLBACK_URL` и Redirects в Discord. Пример портов в README: 3080/3081.
- В этой ревизии не воспроизводилось; перед изменением окружения проверь
  фактические порты и текст ошибки.

## Docker Desktop запущен, но движок не готов

- Источник: README.md, «Запуск Docker Desktop из терминала».
- Диагностика: `docker info` должен показывать сервер, а не ошибку подключения.
- В README описан перезапуск Docker/WSL. Прежде чем останавливать процессы
  или выполнять `wsl --shutdown`, учти другие контейнеры и работающие задачи.
- В этой ревизии не воспроизводилось.

## OAuth не возвращает на сайт

- Источник: README.md, «Вход через Discord (OAuth2)».
- Проверить совпадение `DISCORD_CALLBACK_URL`, фактического порта API
  и Redirects приложения Discord; callback заканчивается на
  `/auth/discord/callback`.
- Это диагностическая подсказка, не доказательство причины любого сбоя OAuth;
  в этой ревизии не воспроизводилось.

## Свежий checkout и тесты с БД

- Источники: README.md, «Вариант B»; `.github/workflows/ci.yml`.
- `packages/shared/dist` генерируется локально и не хранится в Git.
  `db:seed`, `db:seed:test` собирают shared и генерируют Prisma-клиент;
  `db:migrate` предварительно собирает shared для автоматического seed.
- CI запускает PostgreSQL integration tests напрямую через
  `pnpm --filter @dkp/api exec jest --runInBand --testPathPattern=database.spec.ts`:
  комментарий workflow указывает, что Turbo strict env не пропускает
  произвольные переменные. Для этих тестов используется
  `ONBOARDING_TEST_DATABASE_URL` тестовой БД.
- Проверка этой записи — чтение README/workflow; сами тесты не запускались.

## Повторная установка поверх остановленного стенда (issue #75)

- Источник: приёмка на VPS 185.199.158.59, 2026-11-08, подтверждено опытом.
- Симптом: установка в новый `DKP_STATE_DIR` при сохранившихся томах проекта
  `dkp-guild` падает на миграциях с Prisma P1000 (authentication failed):
  том `dkp-guild_db-data` хранит старый пароль БД, а новая конфигурация
  генерирует другой.
- Проект рассчитан на одну установку на сервер; параллельный второй стенд
  с тем же Compose-проектом не поддерживается.
- Обход: перед переустановкой удалить контейнеры и тома проекта
  (`docker rm` + `docker volume rm` по метке
  `com.docker.compose.project=dkp-guild`), затем повторить `dkp start`.
- Повторная проверка: чистая установка в `/root/dkp-stage/state` после
  удаления томов прошла успешно (stage.suneclipse.ru).

## Тесты установщика только на Linux

- Источник: локальный прогон 2026-11-08 на Windows-хосте.
- `installer/test_dkp.py` падает на Windows: `os.fchmod` отсутствует
  (5 ошибок из 10). Это ограничение платформы разработки, а не регрессия:
  установщик целит Ubuntu. На Ubuntu 24.04 все 10 тестов проходят.
- Проверка: `python3 -m unittest test_dkp` в каталоге с `dkp`, `compose.yml`
  и `Caddyfile` на Linux.

## Как пополнять

Для нового подтверждённого бага укажи дату, Issue, симптом, способ
воспроизведения, источник/проверку и безопасный обход, если он известен.
Предположения помечай явно. После исправления убирай устаревший обход
или оставляй краткую ссылку на исправление, если контекст ещё полезен.
