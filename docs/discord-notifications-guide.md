# Как настроить Discord-бота для уведомлений

Инструкция для главы гильдии и администратора сайта. Бот публикует анонсы
ивентов, напоминания, заявки об отсутствии и результаты лотов. Он добавляется
на **сервер Discord**, а доступ к нужным каналам настраивается отдельно.

Для production сначала нужен релиз сайта, в котором реализован бот. Stage и
production используют отдельные настройки, ботов и Discord-серверы: тестовый
бот не должен публиковать сообщения на боевом сервере.

## Что понадобится

- Доступ к [Discord Developer Portal](https://discord.com/developers/applications)
  для создания приложения и получения токена.
- Права на добавление приложений и настройку каналов Discord-сервера гильдии.
  Бота может добавить глава сервера или человек с необходимыми правами.
- Доступ администратора к production-серверу сайта для изменения файла
  `/opt/dkp-production/.env.production` и применения настроек.
- Учётная запись Главы или Админа на сайте для выбора каналов.

При необходимости действия могут выполнить разные люди: токен передают только
администратору сервера сайта по защищённому каналу. ID сервера и каналов не
являются токеном и нужны для настройки маршрутов уведомлений.

## 1. Создайте приложение и получите токен

1. Откройте [Discord Developer Portal](https://discord.com/developers/applications),
   войдите и нажмите **New Application**. Задайте понятное имя, например
   `Guild Notifications`.
2. Откройте созданное приложение и раздел **Bot**. Скопируйте токен бота.
   Если Discord предлагает **Reset Token**, используйте эту кнопку для
   получения нового токена и сохраните его в безопасном месте: сброс делает
   предыдущий токен недействительным.
3. Не отправляйте токен главе гильдии вместе со ссылкой-приглашением, не
   размещайте в чате, Git, скриншотах или журналах. При утечке сбросьте токен
   в Developer Portal и замените его на сервере сайта.

Токен бота отличается от `DISCORD_CLIENT_SECRET`, используемого для входа на
сайт через Discord. Для уведомлений не требуется включать привилегированные
Gateway Intents или создавать slash-команды.

## 2. Создайте ссылку и добавьте бота на сервер гильдии

1. В Developer Portal откройте приложение и раздел **Installation**.
   Включите **Guild Install**, в **Install Link** выберите **Discord Provided
   Link**, а в настройках установки сервера выберите scope `bot`. Для
   уведомлений scope `applications.commands` не нужен.
2. В правах бота выберите только **View Channels** («Просматривать каналы») и
   **Send Messages** («Отправлять сообщения»). Это минимальные права для работы
   сайта; **Administrator** и управление сервером, ролями или каналами боту
   не требуются. При необходимости дополнительные ограничения задаются в
   настройках конкретных каналов Discord.
3. Скопируйте ссылку установки приложения (**Install Link**) и отправьте её
   главе гильдии. Если установка недоступна другому человеку, проверьте
   настройку **Public Bot** в разделе **Bot**: у приватного бота установка
   ограничена владельцем приложения и его командой.
4. Глава открывает ссылку, выбирает **Add to server / Добавить на сервер**,
   выбирает сервер гильдии, проверяет запрошенные права и подтверждает
   авторизацию. При отсутствии сервера в списке проверьте права главы на
   управление сервером и добавление приложений.
5. В списке участников или разделе интеграций сервера убедитесь, что бот
   добавлен. Ссылка приглашает бота на сервер целиком; доступ к каждому
   используемому каналу проверяется отдельно ниже.

Названия пунктов Discord могут немного отличаться в зависимости от языка и
версии интерфейса. См. также [официальное руководство Discord по созданию
бота](https://docs.discord.com/developers/quick-start/getting-started).

## 3. Подготовьте каналы и доступы

Создайте или выберите текстовые каналы. Все четыре типа уведомлений, включая
заявки об отсутствии, могут приходить в общий канал или в разные каналы.
Уведомление об отсутствии содержит ник, период и название ивента, если
заявка относится к ивенту. Причина отсутствия в Discord не передаётся.

Для каждого выбранного канала откройте **Настройки канала → Права доступа** и
разрешите боту или его роли **Просматривать канал / View Channel** и
**Отправлять сообщения / Send Messages**. Права категории и канала могут
переопределять серверные права бота. Если гильдия использует закрытый канал,
проверьте права его читателей в Discord. Назначение РЛ на сайте не выдаёт
права на канал автоматически.

## 4. Скопируйте ID сервера и каналов

1. В Discord откройте **Настройки пользователя → Расширенные** и включите
   **Режим разработчика / Developer Mode**.
2. Нажмите правой кнопкой по значку сервера гильдии → **Копировать ID сервера**.
   Это `DISCORD_GUILD_ID`: он нужен администратору сайта.
3. Нажмите правой кнопкой по каждому выбранному текстовому каналу →
   **Копировать ID канала**. Сохраните, какому типу уведомлений соответствует
   каждый ID: их позже вводят на сайте.

ID — это длинное число. Не путайте ID сервера, ID приложения, ID пользователя
и ID канала. Подробнее: [инструкция Discord по копированию ID](https://support.discord.com/hc/en-us/articles/206346498-Where-can-I-find-my-User-Server-Message-ID).

## 5. Запишите токен и ID сервера в production

Этот шаг выполняет администратор сервера сайта. Для текущей установки
production находится в `/opt/dkp-production`; stage имеет отдельный файл в
`/opt/dkp-guild-site`.

1. Подключитесь к VPS и откройте существующий файл production:

   ```bash
   ssh dkp-stage
   sudo nano /opt/dkp-production/.env.production
   ```

2. Найдите существующие строки и укажите значения после знака `=`. Если строк
   нет, добавьте их по одному разу. Пример ниже содержит заглушки — замените
   их настоящим токеном и числовым ID **боевого сервера**, без угловых скобок:

   ```dotenv
   DISCORD_BOT_TOKEN=ТОКЕН_БОТА
   DISCORD_GUILD_ID=ID_СЕРВЕРА_DISCORD
   ```

3. В `nano` сохраните файл: **Ctrl+O**, **Enter**, затем **Ctrl+X**. У файла
   должны оставаться ограниченные права доступа (`0600`); не выводите его
   содержимое в чат и журналы.
4. Примените конфигурацию через обычный production-процесс развёртывания:
   API-контейнер должен быть **пересоздан**, простого сохранения файла
   недостаточно. Используйте согласованный релиз и workflow **Deploy** для
   окружения `production`, как описано в [README](../README.md#деплой-через-github-actions).
   Если нужный релиз уже установлен, согласуйте его повторное развёртывание с
   администратором. Не подставляйте в production тестовые токен или ID.

Без токена или ID сервера отправитель отключён. Для установки через отдельный
релизный installer им соответствуют переменные `DKP_DISCORD_BOT_TOKEN` и
`DKP_DISCORD_GUILD_ID` в его конфигурации; порядок применения описан в
[документации установщика](../installer/README.md).

**ID каналов в `.env.production` не прописываются.** Они настраиваются на
сайте после применения токена и ID сервера.

## 6. Выберите каналы на сайте

1. Войдите на сайт как Глава или Админ, откройте **Настройки** и найдите
   раздел **Discord**: <https://suneclipse.ru/settings>.
2. Вставьте числовые ID в поля **Анонсы ивентов**, **Напоминания**,
   **Заявки об отсутствии** и **Итоги лотов**. Пустое поле отключает только
   этот вид уведомлений. Один ID можно указать в нескольких полях.
3. Заполните **Причина изменения**, например `Первичная настройка бота`, и
   нажмите **Сохранить каналы**. Сайт проверит принадлежность каналов
   настроенному серверу и права бота. Изменение записывается в аудит.
4. Для каждого включённого типа нажмите **Проверить сохранённый канал**,
   затем **Проверить статус сообщения**. Кнопка проверяет именно сохранённый
   канал, поэтому сначала сохраните изменения. Дождитесь сообщения
   «Тестовое сообщение доставлено в Discord» и проверьте канал в Discord.

Интервал напоминания меняется в общих настройках сайта; по умолчанию это
15 минут. Пробная кнопка проверяет доставку, а не все сценарии: для полной
проверки создайте тестовый ивент и убедитесь, что пришли анонс и напоминание.

## Если сообщения не приходят

- **«Бот или сервер Discord ещё не настроен в окружении»** — проверьте оба
  значения в production-файле и пересоздание API; убедитесь, что открыта нужная
  версия сайта с поддержкой бота.
- **Канал не найден или недоступен** — проверьте ID сервера и канала, что бот
  добавлен именно на этот сервер, и что выбран текстовый канал.
- **Боту нужны права просмотра и отправки** — проверьте оба права в канале и
  его категории, включая явные запреты. Для закрытого канала настройте доступ
  бота отдельно.
- **Сообщение ожидает отправки** — подождите и снова нажмите проверку статуса;
  временные ошибки Discord и сети повторяются автоматически. Если статус
  долго не меняется или отображается ошибка, обратитесь к администратору сайта.
- **РЛ не видит канал отсутствий** — назначение на сайте не меняет Discord-роли;
  проверьте доступ конкретного РЛ или его роли в настройках Discord.
- **Изменили или скомпрометировали токен** — сбросьте его в Developer Portal,
  обновите production-файл и примените конфигурацию пересозданием API.

Подробнее об очереди и диагностике сервера — в разделе
[«Discord-бот уведомлений» README](../README.md#discord-бот-уведомлений).
