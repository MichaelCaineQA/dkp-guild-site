## Верхняя часть

- ✅ Заголовок страницы + описание, о чём она.
- ✅ Ниже слева — горизонтальный список подразделов: **События** и
  **Календарь**; клик переключает подвкладки.
- ✅ Кнопка **«Создать ивент»** — доступна **Главе, Офицерам и Админам**
  (вброс [В], 2026-11-06). Клик → **модалка создания ивента** (см. ниже).
  ✅ Кнопка расположена **справа от переключателя «События / Календарь»**
  (решено [В], ревизия, ответ 13).

## Модалка «Создать ивент»

Поля (вброс [В], 2026-11-06):

| Поле | Обязательное | Вид |
|---|---|---|
| Название ивента | ✅ | текст |
| Тип ивента | ✅ | выбор из редактируемого справочника типов ивентов (PLAN.md 2.1; `/event-types`) |
| Описание | нет | текст |
| Временной промежуток (начало–конец) | ✅ | **датапикер**; подпись у поля: время в таймзоне пользователя |
| Количество ДКП-очков за присутствие | ✅ | положительное целое число (> 0), как в общей схеме `createEventApiSchema`; плата фиксируется при создании |
| Рейд-лидер | ✅ | выбор из одобренного состава гильдии (`/members`); назначение не зависит от ранга игрока (PLAN.md 2.6) |
| Состав | ✅ | вся гильдия (по умолчанию) / КП / пак — этап 3 (PLAN.md 2.1, решение 19); при выборе КП список паков фильтруется по ней; выбранная группа показывается в карточке ивента |

При назначении КП/пака состав приглашённых считается **динамически** по
текущему составу группы на момент ивента (PLAN.md 2.1, решение 19): вошёл
в пак до старта — приглашён, переведён — нет; отдельного снимка при
создании нет.

- ✅ Внизу — кнопка **«Принять»** → создаётся мероприятие; оно появляется в
  списке событий и в календаре.
- ✅ **Шедулинг повторов** (решено [В], 2026-11-06): поле «повторять»:
  нет / ежедневно / еженедельно (дни недели) + дата окончания серии —
  создаётся серия ивентов по шаблону (уже поддержано PLAN.md 2.1 «повторяющиеся
  ивенты серией»); «нет» — обычный одиночный ивент.

### Редактирование, отмена и удаление

- ✅ **Глава, Админ и Офицер** управляют любыми ивентами; **назначенный РЛ** —
  только своим (решено [В], ревизия, ответ 14).
- ✅ Доступны редактирование и отмена. **Удаление — только для
  запланированного ивента**; плата ДКП после создания **неизменна**.
- ✅ После завершения обычное редактирование закрыто; остаются просмотр и
  корректировка итогов РЛ/Главой/Админом. Отменённый ивент — только просмотр
  (решено [В], ревизия, ответ 26; [08-event-card.md](08-event-card.md)).
- Кнопки без права на действие скрываются; ручные изменения фиксируются
  в AuditLog.

## Подвкладка «События»

### Левая часть: список событий календарной недели (пн–вс)

Каждая запись: **дата события, время, название, количество человек, которые
будут присутствовать** (считаются все, кто не пометил отсутствие) и кнопка
**«Не приду»**.

- ✅ Клик по кнопке «Не приду» → модалка: просьба указать причину
  (**необязательное** поле) + кнопка «Отправить».
- ✅ Отправка → игроку добавляется **запись об отсутствии** на мероприятие и
  автоматически проставляется статус участия «отсутствовал по уважительной
  причине» (соответствует механике авто-EXCUSED при закрытии ивента — PR #31).
- ✅ Клик по записи в любом месте, кроме кнопки, → в правой части экрана
  показывается информация по событию (см. ниже).

✅ Навигация по неделям — **стрелками, в обе стороны** (прошлое и будущее)
(решено [В], 2026-11-06) ·
✅ счётчик присутствующих — формат **«N/M»** (пойдут / все приглашённые)
(решено [В], 2026-11-06) ·
✅ **прошедшие события затемняются**, как на дашборде (решено [В], 2026-11-06) ·
✅ Пустое состояние: **«На этой неделе событий нет»**
(решено [В], ревизия, ответ 15).

### Правая часть: карточка выбранного события

Сверху вниз:

1. **Информация**: название, время до начала события, дата и время начала,
   местоположение события, ниже — описание мероприятия.
2. **Раздел «Моё участие»**: текущий статус игрока.
   - Если отметился отсутствующим → **«Не буду»**, иначе → **«Буду»**.
   - ✅ Сменить статус можно здесь:
     - на «не буду» — действие аналогично кнопке «Не приду» в списке
       (модалка с причиной → запись об отсутствии);
     - на «буду» — **запись об отсутствии удаляется**.
3. **Список участников** — сортировка по КП и пакам: сначала все игроки
   КП1 Пака 1, затем КП1 Пака 2, затем КП2 Пака 1 и т.д.
   - ✅ Чтобы список не разрастался, КП и паки — **сворачиваемые группы
     (аккордеон)**; вид подтверждён [В], 2026-11-06.
   - ✅ Заголовок группы: имя пака/КП + количество людей относительно всего
     состава пака/КП — формат **«N/M»**, например «4/5» (см. заметки ниже).

- ✅ Пока событие не выбрано: **«Выберите событие из списка»**
  (решено [В], ревизия, ответ 15).
- Строка участника: **аватар, ник с рангом, класс, боевая роль**;
  **GS — только Главе и Админу** (решено [В], ревизия, ответ 16).
  Назначение РЛ или лидерство КП/пака не открывает GS в карточке ивента.
  Полное правило видимости — [07-profile.md](07-profile.md).
- ✅ Завершённый ивент — просмотр и корректировка итогов РЛ/Главой/Админом;
  отменённый — только просмотр. Подробнее: [08-event-card.md](08-event-card.md).

### Отметка «Увидел» на отсутствии

- ✅ Доступна **в обоих местах**: рядом с отсутствующим игроком в карточке
  ивента и в отдельном списке отсутствий (`/absences`)
  (решено [В], ревизия, ответ 17).
- Оба места показывают одну и ту же отметку заявки; она не меняет статус
  отсутствия. Кнопка видна только пользователям с правом на это действие;
  ручное действие фиксируется в AuditLog.

## Подвкладка «Календарь»

✅ Набор **плиток календарных дней за месяц** с прокруткой помесячно
(«как сделано и сейчас» — текущая реализация `apps/web/app/schedule/page.tsx`).

- В плитке дня — записи о **предстоящих в этот день событиях**, отсортированные
  по времени.
- ✅ У записи видно только **время события и название**.
- ✅ Клик на событие → модалка **КАРТОЧКА СОБЫТИЯ** — содержимое такое же,
  как карточка в правой части подвкладки «События» (инфо + «Моё участие» +
  участники).

✅ Показываются и **прошедшие** события, затемняются как в списке недели
(решено [В], 2026-11-06) ·
✅ Больше 4 событий в дне: показываются 4, внизу плитки счётчик **«+N»** —
сколько записей скрыто ·
✅ **Сегодняшний день подсвечивается** (решено [В], 2026-11-06) ·
✅ Клик по пустой плитке дня **ничего не делает** (решено [В], 2026-11-06).

## Заметки для реализации

- Удаление записи об отсутствии при «Буду» — ок с архитектурой: append-only
  касается только `DkpEntry`; заявки на отсутствие — отдельная сущность.
- Счётчик присутствующих = все активные игроки минус заявки на отсутствие по
  этому событию; формат «N/M».
- Календарные даты и время ивентов — UTC в БД, отображение в таймзоне
  игрока (правило 5 AGENTS.md). Таймлайн **внутриигровых суток** — отдельная
  единая для сервера шкала, одинаковая всем (ревизия, ответ 23).
- Заголовки КП/паков в списке участников: имя + счётчик людей «N/M» от
  состава (формат как у событий).

Решено (2026-11-06): навигация по неделям стрелками в обе стороны; аккордеон
КП/паков; карточка с дашборда — модалка, как в календаре; в календаре
показываются и прошедшие (затемняются), лимит 4 записи + «+N», подсветка
сегодня, клик по пустой плитке — ничего; затемнение прошедших в списке недели;
счётчик «N/M»; кнопка «Создать ивент» (Глава/Офицеры/Админы), модалка создания
и повторы (нет/ежедневно/еженедельно + конец серии).
