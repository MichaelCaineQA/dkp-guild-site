# Лог действий

Статус: черновик · Источник: [В] шестой вброс 2026-11-06

## Роут и доступ

- Пункт «ЛОГ ДЕЙСТВИЙ» боковой шторки (см. [00-common.md](00-common.md)).
- ✅ Доступ: **все авторизованные пользователи** (весь журнал, без деления по
  ролям). Цель кнопки «Перейти в лог действий» на дашборде (последние 10
  записей — см. [02-dashboard.md](02-dashboard.md)).

## Содержимое

- ✅ Список **всех действий** с:
  - изменениями **ДКП**;
  - составом **КП и Паков**;
  - **лотами на аукционе**;
  - **событиями**.
- ✅ Оформление — список (лента записей).
- ✅ Сортировка: **всегда от новых к старым** (не переключается).

## Пагинация и фильтры

- ✅ Пагинация с выбором размера страницы: **10 / 50 / 100** записей.
- ✅ Фильтр по **типу сущности** — **плоский список**: ДКП / КП / Пак /
  лот / событие (решено [В], 2026-11-06).
- ✅ Фильтр по **пользователю, совершившему действие** (+ **системные**
  действия, автор — «Система»).
- ✅ Фильтр **по дате** (диапазон; решено [В], 2026-11-06). Счётчика всего
  записей **нет** (решено [В], 2026-11-06).

## Открытые вопросы

1. Фильтры комбинируются (по умолчанию — да: тип + пользователь + дата)?

Решено (2026-11-06):

- Поля записи — **кто / что / над чем / когда**, без кликабельных ссылок из
  записей.
- **Системные действия** («сделай как правильно», делегировано [В]):
  автор — **«Система»** (псевдо-пользователь), примеры: авто-EXCUSED при
  закрытии события, автоматические начисления по итогам. В фильтре по
  пользователю — отдельная опция «Система».
- Чек-ин коды: в логе только факт «код сгенерирован», сами коды не пишутся
  никогда.
- Фильтр типов — плоский список; есть фильтр по дате; счётчика всего нет.

## Заметки для реализации

  требует записи всегда, видимость записей фильтруется на уровне API.
- Дашборд уже показывает «10 последних записей» — тот же источник, срез.
