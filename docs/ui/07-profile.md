# Профиль игрока

Статус: черновик · Источник: [В] восьмой вброс 2026-11-06

## Роут и доступ

- Попасть: клик по **никнейму игрока где угодно** — в шапке сайта (свой
  профиль) или в списках игроков, где игрок фигурирует (дашборд «Моя
  команда», состав, участники события и т.д.).
- ✅ Отображение элементов и доступность действий **разные для каждой роли**.

## Содержимое профиля (все поля)

- Никнейм игрока
- Роль на сайте
- Класс игрока
- Роль в игре
- GS
- Кнопка добавления скриншотов

## Матрица прав по ролям

| Роль | Видимые поля | Редактирование |
|---|---|---|
| **Сам игрок** (свой профиль) | ✅ все поля | ✅ все поля (включая добавление скриншотов) |
| **Админ** | ✅ все поля | ❌ нет, только просмотр |
| **Глава** | ✅ все поля | ❌ нет, только просмотр |
| **Лидер КП, в которой состоит игрок** | ✅ все поля | ❌ нет, только просмотр |
| **Лидер Пака, в котором состоит игрок** | ✅ все поля | ❌ нет, только просмотр |
| **Рядовой** (чужой профиль) | ✅ только ник, роль на сайте, роль в игре, класс | ❌ GS и скриншоты **не видны** |

Решения [В], 2026-11-06:

- **РЛ — не роль**, а ответственный за событие (поле с id пользователя у
  сущности Event). Расширенные настройки РЛ имеет только в карточке того
  ивента, на который назначен. В профиле прав РЛ не даёт.
- **Гостям (неавторизованным) профиль недоступен вообще.**
- **GS и скриншот редактируются парой** (как при регистрации).
- Скрытие GS/скриншотов и права доступа — в `packages/shared` с юнит-тестами
  в том же PR (правило 6 AGENTS.md); фильтрация на уровне API.

Решено [В], 2026-11-06: скриншотов **может быть несколько**; правка своего
профиля в AuditLog **не пишется**. Кнопка добавления скриншотов — только на
своём профиле (редактирование чужих недоступно, см. матрицу).
