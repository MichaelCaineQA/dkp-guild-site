## Роут и доступ

- Пункт «Состав гильдии» боковой шторки (см. [00-common.md](00-common.md)).
- Доступ: ✅ авторизованные и одобренные игроки. Гостям доступен экран

## Подвкладка «Пак»

- ✅ Изначально — **пустой список + фильтр по Пакам**; чтобы отобразился
  список, нужно выбрать Пак из существующих.

### Форма создания Пака

- ✅ **КП** — первое поле: Глава/Админ выбирает из существующих КП;
  у лидера КП его собственная КП предзаполнена и недоступна для изменения
  (решено [В], ревизия, ответ 22). Список доступных игроков зависит от
  выбранной КП.
- ✅ Ввод **названия пака** (поле названия обязательно — решено [В], вброс 5).
- ✅ Строка поиска **по всем игрокам в КП Пака** (поиск по нику) + пустой
  список под ней.
- ✅ Клик по найденному игроку → игрок добавляется в список.
- ✅ Под списком кнопка «Принять» → игроки **переносятся из других паков в
  этот**.
- ✅ **Ограничение: добавлять можно только игроков из одного и того же КП!**
- ✅ Можно создавать **пустой пак** (без игроков) — решено [В], 2026-11-06.

## Заметки для реализации

- Все действия здесь — ручные: **каждое обязано писать AuditLog** (правило 4
  AGENTS.md): перемещение игрока, создание КП/пака, перенос паков/игроков,
  смена лидеров, приём заявки.
- **Лидерство — отдельные поля в БД** (решено [В], вброс 5): у сущности
  **Пак** — поле-ссылка (id участника) на лидера пака; у сущности **КП** —
  аналогичное поле на лидера КП. Т.е. «лидер пака» и «лидер КП» —
  независимые роли, каждая хранится на своей сущности. Значки: лидер КП —
  **золотая корона**, лидер пака — **серебряная корона** (решено [В],
  2026-11-06); «глава пака» на дашборде = лидер пака (серебряная корона).
- **Иерархия и правила переносов** (обновлено [В], 2026-11-06): паки
  переносятся между КП; игроки переносятся **и между паками, и между КП**
  (оба поля модалки «Переместить» редактируемые, список паков фильтруется по
  выбранному КП). При создании пака по-прежнему — только игроки одного КП.
- Инварианты: игрок принадлежит ровно одному паку; пак принадлежит ровно
  одному КП; при переносе пака КП всех его игроков обновляется.
- При переносе лидера (игрока из пака / пака из КП) **лидерство снимается**
  (не передаётся автоматически).
- Хранить **дату добавления игрока в пак** — нужна для сортировки «Моя
  команда» на дашборде (fallback: дата регистрации).
- **История принадлежности** (PLAN.md 2.7, решение 19): каждый перенос
  игрока в другой пак и пака в другую КП дополнительно пишется записью
  истории с датой — будущая статистика закрепляет результаты за группой
  на момент ивента, а не по текущему составу.
- Прайм-тайм: интервалы в таймзоне игрока; БД хранит день недели и минуты
  (PLAN.md 2.5, решение 19).
