# Карточка мероприятия (проведение ивента)

Статус: вопросы ревизии согласованы (2026-11-06) · Источник: [В] вброс 10, 2026-11-06

Единая карточка ивента: открывается с дашборда, из календаря (модалка) и из
списка событий расписания (правая панель) — см. [03-schedule.md](03-schedule.md).
Здесь описан **жизненный цикл** и части, зависящие от статуса ивента и роли
пользователя. Базовая инфа (название, время, место, описание, «Моё участие»,
список участников с группировкой КП/пак) — в [03-schedule.md](03-schedule.md).

## Роли и статусы

- Коды видят управляющие ивента: **Глава, Админ, любой Офицер и назначенный
  РЛ**. Глава, Админ и Офицер могут проводить любые ивенты. Назначенный РЛ
  проводит свой ивент независимо от ранга (PLAN.md 2.6).
- Статусы ивента: запланирован → идёт → завершён (+ отменён, PLAN.md 2.1).

## Таймлайн игрового времени

- ✅ Внутри карточки вычисляется **таймлайн с временем внутриигровых суток**:
  показывает, какое время суток (день/ночь) будет в игре в каждый момент
  ивента. Основа — `getGamePhase`; якорь цикла и длительности фаз задаются
  настройками гильдии (по умолчанию день 90 мин / ночь 30 мин).
- ✅ Вид — **горизонтальная полоса с цветными участками дня/ночи**, иконками
  солнца/луны и подписями времени переходов (решено [В], ревизия, ответ 23).
- ✅ Шкала и подписи — **по единому внутриигровому времени сервера**:
  таймлайн рассчитывается и показывается **одинаково всем игрокам**, без
  перевода в их локальные таймзоны. Это шкала игровых суток; обычные даты
  и время начала/конца мероприятия описаны отдельно в расписании.

## Чек-ин: стартовый код (кнопка «Начать ивент»)

1. ✅ Когда рейд собрался, управляющий ивента нажимает
   **«Начать ивент»** — с подтверждением, в любой момент, в том числе раньше
   планового начала. Ивент получает статус «идёт», и сразу управляющим
   в карточке становится виден **трёхзначный код подтверждения** (стартовый)
   — когда открываются окна, см. ниже.
2. ✅ Всем авторизованным становится доступна кнопка **«Подтвердить участие»**.
3. ✅ Клик → модалка с **4 кнопками**, на каждой — трёхзначный код; на одной —
   правильный (виденный РЛ на шаге 1), **3 ложных генерируются случайно**
   (решено [В], 2026-11-06). Одна попытка — как в существующей механике чек-ин
   кодов (PLAN.md 2.5, PR #30), здесь 1 правильный из 4.
4. ✅ После клика по любому варианту — модалка подтверждения.
5. ✅ **Правильный код** → игроку начисляется **первая половина** ДКП-стоимости
   ивента.
6. ✅ **Неправильный** → повторный выбор **блокируется** (одна попытка).
7. ✅ Код действует **3 минуты**. По истечении окна: код **исчезает** у
   управляющих, у участников **пропадает возможность
   отметиться**; после окончания ивента управляющий может отметить ввод кода
   вручную (решено [В], 2026-11-06; см. «Итоги»).

## Чек-ин: финальный код (после окончания)

1. ✅ После окончания ивента управляющим виден **второй трёхзначный
   код**; всем — кнопка **«Подтвердить завершение»**; механика та же
   (4 кнопки, одна попытка, вторая половина ДКП-стоимости при успехе).
2. ✅ Код действует **3 минуты**; по истечении — как у стартового: код
   исчезает у управляющих, отметиться нельзя, возможна ручная отметка
   управляющим по итогам (решено [В], 2026-11-06).

## Когда открываются окна кодов (решение 23, #318, 2026-11-25)

Управляющий может открыть окно чек-ина кнопкой в любой момент относительно
планового времени.

| Кнопка | Где | Что делает |
|---|---|---|
| **«Начать ивент»** | карточка запланированного ивента, страница проведения | статус «идёт» + сразу окно стартового кода, даже если до планового начала ещё далеко |
| **«Завершить ивент»** | карточка идущего ивента, страница проведения | статус «завершён» + сразу окно финального кода, раньше или позже планового окончания |

- ✅ Обе кнопки требуют **подтверждения**: окно каждой фазы открывается один
  раз, а завершённый ивент нельзя вернуть в идущий. Подтверждение завершения
  напоминает, что после него добавить дроп и лоты на ивент нельзя.
- ✅ После нажатия карточка **остаётся открытой** и сразу показывает код —
  РЛ оглашает его в голосовом чате, не открывая карточку заново.
- ✅ Финальный код виден и вводится, пока ивент уже «завершён»: окно финала
  открыто ещё 3 минуты. Затем в карточке — «Окно закрылось».
- ✅ Без нажатия управляющего в блоке кода: «Окно стартового кода откроется
  кнопкой „Начать ивент“».
- ✅ Кнопка «Досрочно запустить финальный код» убрана — её заменило
  «Завершить ивент».

## Итоги: корректировка статусов участников

Управляющие ивента могут подвести и скорректировать итоги после его завершения.

### Автостатусы (по вводам кодов + отсутствиям)

| Вводы кодов | Условие | Статус по умолчанию |
|---|---|---|
| оба кода | — | **«Участвовал»** |
| ни одного | есть заявка об отсутствии на это время | **«Отсутствовал по ув. причине»** |
| ни одного | нет заявки | **«Отсутствовал»** |
| только стартовый | — | **«Ушёл раньше»** |
| только финальный | — | **«Опоздал»** |

- ✅ **ДКП по кодам** (уточнено [В], 2026-11-06): не ввёл **ни одного** кода —
  автоматически не начисляется **ничего, даже частично**. Ввёл один код —
  начисляется соответствующая половина: «Ушёл раньше» (только стартовый) —
  первая, «Опоздал» (только финальный) — вторая. Названия статусов исправлены
  по ответу [В] 25 в ревизии. Сверх этого — только
  ручные бонусы и штрафы от управляющих ивента.

Соответствие системным статусам посещения (`AttendanceStatus`, PLAN.md 2.2):

| Подпись | Статус |
|---|---|
| Участвовал | `PRESENT` |
| Опоздал | `LATE` |
| Ушёл раньше | `LEFT_EARLY` |
| Отсутствовал | `NO_SHOW` |
| Отсутствовал по ув. причине | `EXCUSED_ABSENCE` |

### Действия управляющих в списке участников

| Кнопка | Что делает |
|---|---|
| **«+ код» (старт)** | виртуально добавить ввод первого кода игроку (в т.ч. для не успевших в 3-минутное окно) |
| **«+ код» (финал)** | виртуально добавить ввод второго кода игроку |
| **«Ув. причина»** | сменить статус на «Отсутствовал по ув. причине»: модалка ввода причины → создаётся **отсутствие на эту дату за игрока** |
| **«ДКП»** (уже есть) | добавить бонусные ДКП или штрафные (число со знаком минус) + **обоснование** |

- ✅ Все корректировки — ручные действия → **AuditLog** (правило 4
  AGENTS.md); ручные ДКП — записи в журнал ДКП с обоснованием.
- ✅ Изменения применяются по кнопке **«Подвести итоги»** — разовое
  подтверждение подготовленных корректировок (решено [В], ревизия, ответ 24).

## Завершённые и отменённые ивенты

✅ Решение [В], ревизия, ответ 26:

- **Завершённый ивент:** доступен просмотр; управляющие ивента
  могут корректировать итоги. Обычное редактирование параметров мероприятия
  закрыто.
- **Отменённый ивент:** только просмотр, без действий по проведению,
  редактированию параметров или корректировке итогов.
- Недоступные действия не показываются. Эти ограничения применяются и
  к правой панели расписания, и к модальной карточке из календаря/дашборда.
- Существующие записи ДКП сохраняются: корректировки завершённого ивента
  добавляются новыми записями, согласно append-only правилу.

## Преемственность с текущей реализацией (PR #33)

Описанный здесь процессинг — **целевая модель** (to-be). Уже реализованный в
PR #33 чек-лист РЛ (ручные отметки посещения, ручные начисления, досрочный
финальный код) — **текущее подмножество** этой модели: кнопки «+код», «ДКП» и
досрочный финал уже существуют и сохраняются; новое — коды за 3 минуты до
начала и после конца с окном 3 минуты, выбор 1 из 4, автостатусы по вводам и
автоначисление половин ДКП-стоимости. Реализация эволюционирует из существующего
функционала без дублирования. Требования и игровые правила остаются в
PLAN.md; все решения этой ревизии перенесены в его разделы 2.1/2.2/2.6
по поручению владельца (2026-11-06). Согласование описания целевой модели
не означает, что она уже целиком реализована в коде.

Уточнение от 25.11.2026 (решение 23, #318): абзац выше описывает состояние
на 2026-11-06. Теперь коды открываются кнопками «Начать ивент» и «Завершить
ивент», а не по расписанию; отдельной кнопки досрочного финального кода
нет — см. «Когда открываются окна кодов».
