# Карточка мероприятия (проведение ивента)

Статус: черновик · Источник: [В] вброс 10, 2026-11-06

Единая карточка ивента: открывается с дашборда, из календаря (модалка) и из
списка событий расписания (правая панель) — см. [03-schedule.md](03-schedule.md).
Здесь описан **жизненный цикл** и части, зависящие от статуса ивента и роли
пользователя. Базовая инфа (название, время, место, описание, «Моё участие»,
список участников с группировкой КП/пак) — в [03-schedule.md](03-schedule.md).

## Роли и статусы

- Коды видят: **Глава, Админ, РЛ ивента** (РЛ — не роль сайта, а ответственный
  за ивент: поле id пользователя у сущности Event).
- Статусы ивента: запланирован → идёт → завершён (+ отменён, PLAN.md 2.1).

## Таймлайн игрового времени

- ✅ Внутри карточки вычисляется **таймлайн с временем внутриигровых суток**:
  показывает, какое время суток (день/ночь) будет в игре в каждый момент
  ивента. Основа — `getGamePhase` (90 мин день / 30 мин ночь), якорь цикла —
  настройка гильдии (PLAN.md, правило 5 AGENTS.md).
- ❓ Вид: полоса с делениями по фазам? подписи?

## Чек-ин: стартовый код (за 3 минуты до начала)

1. ✅ **За 3 минуты до начала** ивента Главе, Админу и РЛ в карточке становится
   виден **трёхзначный код подтверждения** (стартовый).
2. ✅ Всем авторизованным становится доступна кнопка **«Подтвердить участие»**.
3. ✅ Клик → модалка с **4 кнопками**, на каждой — трёхзначный код; на одной —
   правильный (виденный РЛ на шаге 1), **3 ложных генерируются случайно**
   (решено [В], 2026-11-06). Одна попытка — как в существующей механике чек-ин
   кодов (PLAN.md 2.5, PR #30), здесь 1 правильный из 4.
4. ✅ После клика по любому варианту — модалка подтверждения.
5. ✅ **Правильный код** → игроку начисляется **первая половина** ДКП-стоимости
   ивента.
6. ✅ **Неправильный** → повторный выбор **блокируется** (одна попытка).
7. ✅ Код действует **3 минуты**. По истечении окна: код **исчезает** у
   управляющих (Глава/Админ/РЛ), у участников **пропадает возможность
   отметиться**; после окончания ивента управляющий может отметить ввод кода
   вручную (решено [В], 2026-11-06; см. «Итоги»).

## Чек-ин: финальный код (после окончания)

1. ✅ После окончания ивента Главе, Админу и РЛ виден **второй трёхзначный
   код**; всем — кнопка **«Подтвердить завершение»**; механика та же
   (4 кнопки, одна попытка, вторая половина ДКП-стоимости при успехе).
2. ✅ Код действует **3 минуты**; по истечении — как у стартового: код
   исчезает у управляющих, отметиться нельзя, возможна ручная отметка
   управляющим по итогам (решено [В], 2026-11-06).
3. ✅ **Досрочный финал**: те, кому виден код (Глава/Админ/РЛ), могут
   **закончить ивент преждевременно** — финальный код показывается сразу же
   (уже реализовано — «досрочный финальный код», PR #33).

## Итоги: корректировка статусов участников

После завершения мероприятия подводит итог **РЛ ивента**; итоги могут
корректировать также **Глава и Админ** (решено [В], 2026-11-06).

### Автостатусы (по вводам кодов + отсутствиям)

| Вводы кодов | Условие | Статус по умолчанию |
|---|---|---|
| оба кода | — | **«Участвовал»** |
| ни одного | есть заявка об отсутствии на это время | **«Отсутствовал по ув. причине»** |
| ни одного | нет заявки | **«Отсутствовал»** |
| только стартовый | — | **«Опоздал»** |
| только финальный | — | **«Ушёл раньше»** |

- ✅ **ДКП по кодам** (уточнено [В], 2026-11-06): не ввёл **ни одного** кода —
  автоматически не начисляется **ничего, даже частично**. Ввёл один код —
  начисляется соответствующая половина: «Опоздал» (только стартовый) —
  первая, «Ушёл раньше» (только финальный) — вторая. Сверх этого — только
  ручные бонусы/штрафы РЛ/Главы/Админа.
- ❓ соответствие статусам PLAN/системы (участвовал/отсутствовал/EXCUSED/
  опоздал/ушёл раньше — сверить с разделом 2.2/2.4 при реализации).

### Действия в списке участников (РЛ / Глава / Админ)

| Кнопка | Что делает |
|---|---|
| **«+ код» (старт)** | виртуально добавить ввод первого кода игроку (в т.ч. для не успевших в 3-минутное окно) |
| **«+ код» (финал)** | виртуально добавить ввод второго кода игроку |
| **«Ув. причина»** | сменить статус на «Отсутствовал по ув. причине»: модалка ввода причины → создаётся **отсутствие на эту дату за игрока** |
| **«ДКП»** (уже есть) | добавить бонусные ДКП или штрафные (число со знаком минус) + **обоснование** |

- ✅ Все корректировки — ручные действия → **AuditLog** (правило 4
  AGENTS.md); ручные ДКП — записи в журнал ДКП с обоснованием.
- ✅ Изменения применяются **по кнопке** (разовое подтверждение итогов; решено
  [В], 2026-11-06). ❓ название кнопки — предложить «Подвести итоги» при
  реализации.

## Преемственность с текущей реализацией (PR #33)

Описанный здесь процессинг — **целевая модель** (to-be). Уже реализованный в
PR #33 чек-лист РЛ (ручные отметки посещения, ручные начисления, досрочный
финальный код) — **текущее подмножество** этой модели: кнопки «+код», «ДКП» и
досрочный финал уже существуют и сохраняются; новое — коды за 3 минуты до
начала и после конца с окном 3 минуты, выбор 1 из 4, автостатусы по вводам и
автоначисление половин ДКП-стоимости. Реализация эволюционирует из существующего
функционала без дублирования; расхождения трактовать в пользу этого файла и
PLAN.md (оформлено ассистентом по поручению «сделай красиво», 2026-11-06).
