# @dkp/web — фронтенд ДКП-системы

Next.js (App Router) + TypeScript strict + Tailwind CSS. UI — только русский.

## Архитектура «редизайн-готовности»

Сайт строится так, чтобы смена дизайна не трогала логику экранов:

```
app/globals.css      ← ТОКЕНЫ: все цвета, радиусы, тени. Единственное место
                        со стилевыми решениями. Смена дизайна = правка этого файла.
components/ui/        ← ПРИМИТИВЫ: единственное место с вёрсткой и Tailwind-классами.
                        Page, Card, Button, Input, Select, Table, Badge, Notice…
app/**/page.tsx       ← ЭКРАНЫ: данные, обработчики, права. Страницы СОБИРАЮТСЯ
                        из примитивов и НЕ пишут стилей сами.
```

**Правило: страница или компонент вне `components/ui` не содержит Tailwind-классов
со стилевыми решениями** (цвета, рамки, тени, радиусы). Разрешены только
утилиты раскладки без визуального смысла: `flex`, `grid`, `gap-*`, `mt-*`,
`w-*`/`max-w-*`, `text-sm`/`text-lg` в разумных пределах. Увидел, что нужен
новый визуальный элемент — добавь примитив в `components/ui`, а не стилизуй
на месте.

Почему так: когда глава гильдии согласует финальный дизайн, перевёрстка =
`globals.css` (токены) + `components/ui` (примитивы). Экраны — данные и
поведение — не переписываются, а значит не ломаются и не требуют ревью логики.

## Экраны

| Маршрут | Что это |
|---|---|
| `/` | Главная (пока — проверка ядра) |
| `/roster` | Состав гильдии (issue #6) |
| `/link` | Заявка на привязку ника |
| `/link-requests` | Очередь заявок для офицеров |
| `/design` | **Витрина дизайна** — все токены и примитивы; показываем главе при согласовании стиля |

Навигация строится в `components/nav-menu.tsx` по правам сессии (матрица 2.6).

## Конвенции

- **Данные страниц** — через `api()` из `lib/api.ts` (сессионная cookie), типы —
  из `@dkp/shared`. Схемы и подписи (ранги, роли) тоже оттуда: не дублируй.
- **Права** — `can(actor, permission)` из `@dkp/shared` по данным `useSession()`.
- **Состояние сессии** — `useSession()` из `components/session-context.tsx`.
- Пока бэкенда для экрана нет, страницу можно делать на моках/заглушках —
  контракт берём из `@dkp/shared` (zod-схемы), тогда подключение API позже
  не меняет вёрстку.
- Тесты — vitest + Testing Library рядом с компонентами (`*.test.tsx`);
  смотри `app/roster/page.test.tsx` как образец (мок `api` и сессии).
- После правок UI прикладывай скриншот в PR (AGENTS.md).

## Команды

```bash
pnpm --filter @dkp/web dev          # http://localhost:3000
pnpm --filter @dkp/web test         # vitest
pnpm lint && pnpm typecheck && pnpm build   # перед PR (из корня)
```

## Трек дизайна (для фронтендера)

1. **Варианты дизайна** — 2–3 направления палитры/типографики как варианты
   токенов в `globals.css` (например, ветки `design/variant-a|b`). Быстрый
   предпросмотр любого варианта — страница `/design`.
2. **Согласование с главой** — показать варианты (staging или локально),
   зафиксировать выбор в issue «Дизайн: согласование».
3. **Перевёрстка** — внести согласованные значения в токены; если меняется
   структура блоков — править только `components/ui`. Страницы не трогаем.
