# @dkp/web — фронтенд ДКП-системы

Next.js (App Router) + TypeScript strict + Tailwind CSS. UI — только русский.

## Архитектура «редизайн-готовности»

Сайт строится так, чтобы смена дизайна не трогала логику экранов. Что где
лежит, роли палитры, типографика и процесс редизайна — **[DESIGN.md](DESIGN.md)**.
Коротко:

```
app/globals.css      ← палитра + шрифт (светлая/тёмная темы). Смена палитры = правка здесь.
components/ui/       ← примитивы: единственное место с вёрсткой и стилями.
app/**/page.tsx      ← экраны: данные, обработчики, права. Стилей не пишут.
```

**Правило:** страница или компонент вне `components/ui` не содержит
Tailwind-классов со стилевыми решениями (цвета, рамки, тени, радиусы).
Разрешены только утилиты раскладки без визуального смысла: `flex`, `grid`,
`gap-*`, `mt-*`, `w-*`/`max-w-*`, `text-sm`/`text-lg` в разумных пределах.
Нужен новый визуальный элемент — добавь примитив в `components/ui`, а не
стилизуй на месте.

## Экраны

| Маршрут | Что это |
|---|---|
| `/` | Приветствие → анкета/ожидание → дашборд после одобрения |
| `/roster` | Состав гильдии (issue #6) |
| `/link` | Анкета вступления (также открывается автоматически на `/`) |
| `/link-requests` | Вкладка «Заявки» состава, только Глава/Админ |
| `/applications/[id]` | Профиль заявителя с GS и приватными скриншотами |
| `/design` | **Витрина дизайна** — палитра и компоненты; канал показа для согласования с главой |

Навигация строится в `components/nav-menu.tsx` по правам сессии (матрица 2.6).

## Конвенции

- **Данные страниц** — через `api()` из `lib/api.ts` (сессионная cookie), типы —
  из `@dkp/shared`. Схемы и подписи (ранги, роли) тоже оттуда: не дублируй.
- **Права** — `can(actor, permission)` из `@dkp/shared` по данным `useSession()`.
- **Состояние сессии** — `useSession()` из `components/session-context.tsx`.
- Пока бэкенда для экрана нет, страницу можно делать на моках/заглушках —
  контракт берём из `@dkp/shared` (zod-схемы), тогда подключение API позже
  не меняет вёрстку.
- Тесты — vitest + Testing Library рядом с компонентами (`*.test.tsx`);
  смотри `app/roster/page.test.tsx` как образец (мок `api` и сессии).
- После правок UI прикладывай скриншот в PR (AGENTS.md) — скриншоты для
  документации PR, а не канал показа дизайна главе: главе показываем живую
  витрину `/design`.

## Команды

```bash
pnpm --filter @dkp/web dev          # http://localhost:3000
pnpm --filter @dkp/web test         # vitest
pnpm lint && pnpm typecheck && pnpm build   # перед PR (из корня)
```

## Трек дизайна (для фронтендера)

Подробно — в [DESIGN.md](DESIGN.md), раздел «Процесс редизайна».

1. **Варианты дизайна** (#23) — 2–3 направления палитры как ветки
   `design/variant-*`; предпросмотр любого варианта — страница `/design`.
2. **Согласование с главой** (#24) — показать живую витрину, зафиксировать выбор.
3. **Перевёрстка** (#25) — палитра в `globals.css`, структура в `components/ui`;
   страницы не трогаем.

До одобрения `AppShell` показывает только приветствие/анкету/ожидание:
шапка и страницы разделов не монтируются. API защищён отдельно.
